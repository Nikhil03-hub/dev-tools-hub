**Branch:** `v3` · **Date:** 2026-10-25 · **Predecessor:** CP1 read-only release-gate verification @ `32685cc`
**Verdict of this task:** the three defects found by that verification are fixed and regression-tested. **CP1 remains PENDING** — it needs the owner's review and an independent approval.

## 1. What was broken, and why the 329-test suite missed it

| ID | Defect | Root cause (measured, not inferred) | Why tests missed it |
|---|---|---|---|
| **B1** | Keyboard trap: Tab and Shift-Tab never left a CodeMirror editor | `@uiw/react-codemirror` defaults `indentWithTab` to **true** (`esm/getDefaultExtensions.js:15`), registering `keymap.of([indentWithTab])` = `{key:"Tab", run: indentMore, shift: indentLess}`. CodeMirror's own upstream default leaves Tab unbound for exactly this reason. Measured: `keydown` → `defaultPrevented: true`, focus unchanged over 6 forward + 4 backward presses. | Every existing focus test pressed Tab *to reach* a control and then inspected that control. None asserted that focus could **leave**. |
| **B2** | Editor focus ring rendered on 3 of 4 edges — left edge absent in both themes | `.cm-gutters` is `position: sticky` with an opaque background, so it paints over the frame's inset `outline`. Measured left-edge pixel coverage: **0/125** (light) and **0/125** (dark); right 125/125, top 108/112, bottom 108/112. | `focus_ring_json_editor_*` asserted `getComputedStyle(...).outlineStyle !== "none"`. Computed CSS reports a ring that never reaches the screen. |
| **B3** | Dark-theme hover contrast 2.34:1 | `--c-accent-hover` served two opposite roles: a **foreground** hover colour (`hover:text-accent-hover`, needs to be light in dark mode) and a **background** under white label text (`hover:bg-accent-hover`, needs to be dark). One token cannot satisfy both. | No test ever measured a rendered foreground/background pair. axe's `color-contrast` rule does not evaluate `:hover`. |

Correction to the verification report: it described Escape as an undocumented escape route. **Escape does not blur the editor** (it is bound to selection-cancel), so pre-fix there was no discoverable keyboard exit at all. B1 was more severe than reported.

## 2. Changes

| File | Change |
|---|---|
| `src/components/JsonEditor.tsx` | `indentWithTab={false}` — restores CodeMirror's default Tab = focus navigation. Single shared wrapper, so it covers every editor in the product. |
| `src/lib/cmTheme.ts` | Frame `outline` replaced with a non-interactive `::after` border at `z-index: 300` (above the sticky gutter's 200), drawn inside the frame so the `overflow-hidden` panes cannot clip it. |
| `src/theme/tokens.css` | New semantic token `--c-accent-strong-hover` — light `72 56 200`, dark `80 63 208` (both blocks). `--c-accent-hover` keeps its foreground role. |
| `tailwind.config.js` | `accent-strong` becomes `{ DEFAULT, hover }` so `bg-accent-strong-hover` resolves. |
| `src/components/Button.tsx`, `src/shell/StaticPage.tsx` | Filled-control hover switched to `hover:bg-accent-strong-hover`. |
| `src/components/CommandPalette.tsx` | Records `document.activeElement` on open; restores focus on close, guarded by `isConnected` + `offsetParent` so a removed or hidden opener is never focused. |
| `src/components/IconButton.tsx` | Optional `expanded` / `controls` props. |
| `src/shell/TopBar.tsx`, `src/App.tsx` | Menu trigger exposes `aria-expanded` bound to real drawer state; `aria-controls="mobile-drawer"` only while the drawer is mounted. |
| `src/shell/MobileDrawer.tsx` | `id="mobile-drawer"` so the control reference resolves. |
| `test/e2e.cjs` | +27 checks (329 → 356), pixel/keyboard infrastructure, and axe + scroll coverage extensions. |

**Decision recorded:** `indentWithTab={false}` removes Tab-to-indent. That is deliberate — the a11y-correct default, and JSON needs no tab indentation. Snippet navigation is unaffected because `autocompletion: false` means no snippet can ever be active in these editors.

## 7. Cosmetic item inspected, deliberately not changed

The home `<h1>` reports `scrollHeight 46 > clientHeight 44` at 1440px and `71 > 70` at 390px. Its computed `overflow` is **`visible`**, so the extra 2px is ink extending past the line box — nothing is clipped. No typography change made; changing `leading-[44px]` would be a visual edit without a defect behind it.

## 8. Remaining risks — explicit

1. **Chromium only.** Every pixel, keyboard and contrast result above was measured in Chromium. Safari and Firefox are untested; WebKit in particular may differ on paint order and `:focus-visible`.
2. **Production headers unverified.** `vite preview` does not serve `_headers`, so the server-delivered CSP was checked by content, not by live response. Must be re-checked on the first real deploy.
3. **Unknown routes return HTTP 200 locally.** Netlify serves `dist/404.html` with a 404 status; unverified until deploy.
4. **Ring shows on pointer focus too.** `:focus-within` (not `:focus-visible`) drives the editor ring, so clicking into the editor also paints it. Kept intentionally: it is the shipped behaviour, `:has(:focus-visible)` would be riskier on the untested browsers, and an always-visible indicator never hides focus.
5. **`Button` `primary` variant is still unused** in P1; it now carries the corrected pair, so the fix applies the first time it is used.
6. `13.5px` editor font remains off the UX_SPEC type scale — accepted trade-off, tracked below.
