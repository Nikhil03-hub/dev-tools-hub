## 2. Root cause

Two independent facts combined, and only the first was known at audit time:

1. **`<mark>` takes its foreground from the user-agent stylesheet.** The highlight `<pre>` declares `text-ink`, but inheritance cannot beat a *declared* value on the element itself, and nothing in `src/` styles `mark`. So the match text rendered as UA black (`rgb(0, 0, 0)`) in **both** themes. In dark mode that is black on `rgb(71, 66, 114)` — the measured 2.29:1.
2. **The fill alpha stacks.** A capture group is a `<span>` *inside* the `<mark>`, so its own `bg-accent/70` composites over the match's `bg-accent/40`, giving an effective 0.82 alpha. The rendered ladder was therefore far more saturated than the class names suggest, and it passed through a mid-tone band where **neither** theme text colour reaches 4.5:1.

The audit's own first measurement of this was wrong in a third way: it compared an un-composited `rgba()` channel as if it were the final colour. Corrected before the fix was designed.

## 3. Why the obvious fix was rejected by measurement

`mark { color: inherit }` was measured at runtime before being adopted. It fixes dark L0 (2.29 → 7.86) but **breaks the first group level in both themes** — light 4.05, dark 3.38 — because the groups then inherit a theme colour that cannot survive the mid-tone band. A one-line CSS change would have traded one failure for two. That is why the ladder itself was retuned.

## 4. The fix

`src/tools/regex/components/MatchHighlight.tsx` only — no global `mark` rule (there is exactly one `<mark>` in the app, so a component-local fix avoids affecting anything else), no new dependency, no token change, no theme change.

- Every highlight level now declares its own foreground: match `text-ink`, groups `text-canvas`.
- Ladder retuned from `/40 → /70 → /85` to `/40 → /80 → /90`, so no rendered level sits in the band where both candidates fail.
- Fixed a latent indexing bug: `assignGroupClasses` used `depth - 1` while `depth` starts at 2 for a direct child, so **`GROUP_CLASSES[0]` was unreachable dead code** and every group collapsed onto a deeper shade. Now `depth - 2`.
- The prior comment claimed text flips to canvas "only at the deepest level"; measured behaviour is that the flip must happen at the *first* group level in both themes. Comment replaced with the measured numbers.

## 10. Limitations and what remains unverified

1. **Chromium only.** No Safari or Firefox claim is made.
2. **Production headers and real 404 status still unverified** — `vite preview` does not serve `_headers`. Deferred to the separate deployment-preview milestone by design.
3. The `/80` level is the tightest at 4.80:1 (light). It clears AA with modest margin; a future palette change to `--c-accent` must re-run these tests, which is what they are for.
4. Match intensity changed visibly (`/70`→`/80`, `/85`→`/90` for groups). This is a deliberate, measured trade: legibility over subtlety. The owner may want a design glance before release.
5. Pre-existing follow-ups untouched and still open: `13.5px` editor font, deploy-time header verification, cross-browser pass, palette restore when the opener unmounts, duplicate Recents/Tools destinations.
