## Bug found by the screenshots, and fixed
The first implementation rendered the mobile drawer as a **56px icon rail**. The cause: the collapsed default was computed as `!(min-width: 1024px)`, so a 390px page started `collapsed = true`, and the drawer reused that state. A drawer of unlabelled icons is unusable.

Fixed in three places: the default is now "tablet only" (`hasSidebar && !wide`), `App` passes `collapsed: false` to the drawer, and `Sidebar` hides the collapse button when `onToggleCollapsed` is omitted. A regression guard was added to `shell_mobile_drawer_opens`: it now asserts the drawer's text contains `JSON Workbench` and `Debug Report`, so an icon-only drawer fails the check even though it is technically "visible".

## Deviations from the spec
1. **Added `src/shell/useMediaQuery.ts`**, which the T-105 file list does not mention. It is required by the spec's own rule that the desktop sidebar is *not rendered* below 768px and that test ids stay unique; the alternative was duplicating a `matchMedia` listener in two components.
2. **Deleted `src/components/PrivacyBadge.tsx`** as well as `Header.tsx`. After the header was removed it had no importers; `PrivacyPopover` supersedes it. Checked first that T-604 (counters build) does not reference its copy.
3. **Scoped focus rings.** `.focus-ring` is applied to shell controls only. That satisfies T-105's own AC4 without pre-empting the global repair of the 17 legacy `outline-none` sites, which stays an open finding for `R-CP1-focus`.
4. **Footer shows `Kbd` (`Ctrl K` on Windows)** instead of a hardcoded `⌘K`. The spec's wording "⌘K Commands" would be false on the owner's machine; `Kbd` already encodes the platform rule.
5. **Two extra e2e checks** (focus ring, console errors) beyond the six specified. Additive only.

## Questions / risks for the reviewer
1. **The focus-ring check exercises the dark theme only** (the shared context runs with `colorScheme: "dark"`). The rule uses `--c-accent`, whose light-theme contrast against every surface was computed at 6.17–6.44:1 and dark at 5.22–5.93:1, but the *browser* assertion runs in one theme. Say the word and `shell_focus_ring_visible` gets a light-theme pass too.
2. **`/privacy/` is still inert in-app.** The "How to verify" link navigates to `/privacy/`, but until T-106 adds `StaticPage`, the route renders the default tool. The prerendered page on Netlify is correct; only client-side navigation is affected, and T-106 is the next task.
3. **Recent duplicates the active tool** in the list (e.g. "Recent → JSON Workbench" above "Data formats → JSON Workbench"). Spec-mandated; worth a design decision later.
4. **`Popover` traps Tab while open.** It is not `aria-modal`, so a screen reader can still reach the page behind it — intentional for a small disclosure. If the reviewer wants a true modal popover, that is a change to the component, not to T-105's wiring.
