## What changed
**New shared components** (`src/components/`): `Button`, `Badge`, `Toggle`, `Segmented`, `Tabs`, `Pane`, `CopyButton`, `DownloadButton`, `EmptyState`, `Tooltip`, `ErrorBoundary`, `ToolSkeleton` — built to UX_SPEC §5, token classes only, `.focus-ring` on every control, ARIA roles (`switch`, `radiogroup`/`radio`, `tablist`/`tab`, `dialog`).

**`src/shell/ToolHost.tsx`**: now wraps every tool in `ToolLayout` and uses the shared `ErrorBoundary` (with a working **Reset tool** that remounts via a changed key) and `ToolSkeleton`. The local duplicates are gone.

**Clipboard correctness** (`src/components/CopyButton.tsx`): `copyAndNotify(text, successMessage?)` awaits `copyText()`, treats a rejected promise **and** a `false` return as failure, and toasts `Copied` only on success or `Copy failed — select and copy manually` otherwise. `CopyButton` uses it; `DebugReportApp` now routes **all three** copy paths through it (`copySanitized`, `copyReport`, `copyAiReport`). No clipboard content is ever logged or included in diagnostics.

**`src/App.tsx`**: the scroll region is explicit, and the main column carries `min-h-0` (see the bug below).

## The bug these checks caught (real, user-facing)
`toollayout_page_scrolls` failed twice, and the cause was not the test. The main column was `<div className="flex min-w-0 flex-col">` inside a `h-screen overflow-hidden` grid. Without `min-h-0` the column grew to **1419 px** inside a **900 px** row; the shell's `overflow-hidden` then clipped it, so the whole docs block was **unreachable — not merely off-screen**. Measured before: the `overflow-y-auto` region had `clientHeight 1367` (it had grown) with `scrollHeight 1367`. After adding `min-h-0`: `clientHeight 848`, `scrollHeight 1367`, `canScroll: true`, and "How to use" sits at y≈938, reachable by scrolling.

Two earlier failures in this task were my own test bugs (measuring `window.scrollY` in a shell that scrolls an inner region; and clicking a copy button that lives behind the Sanitized tab). Both were fixed in the checks, not in the product.

## Deviations
1. **`DebugReportApp.tsx` was changed**, although the spec says the six V1 tool files are not changed. The copy-failure requirement cannot be met while the tool keeps calling `copyText()` and ignoring its result; the change is limited to the three copy handlers. No markup, test id or layout changed.
2. **`CopyButton.tsx` also exports `copyAndNotify`** so non-button copy actions (share/AI) share one honest implementation instead of three.
3. **AC4 scroll is measured on the shell's main region**, not `window`. The app is a fixed-height shell; the content scrolls inside `main`. The check asserts the region genuinely scrolls and that the docs heading is below the fold.
