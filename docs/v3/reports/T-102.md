## Deviations from the spec
- **None in behaviour.** Two notes:
  1. The spec sets both normal and `:hover` scrollbar thumb colour to `rgb(var(--c-scroll))`, so hover no longer differs. Implemented exactly as written; recording it because it is a deliberate loss of hover feedback, not an oversight.
  2. In the new `theme` e2e section, the `backToSystem` result is used only in the diagnostic string, not asserted — this is exactly what step 11(d) specifies ("click until the preference is back to system … check `errors.length === 0`"). Flagged below rather than silently strengthened, because the spec enumerates its e2e edits precisely.

## Questions / risks for the reviewer
1. **Strengthen `theme_no_console_errors`?** A broken cycle that never returns to "system" would currently still pass, because `backToSystem` is not in the assertion. Adding `&& backToSystem` is strictly stronger and costs nothing. I did not do it unasked; say the word and it becomes a one-line follow-up.
2. **Focus indicators — a verified defect this task does not cover.** See `docs/v3/reports/A11Y-focus-indicator-finding.md`. In short: 17 places remove the focus outline, 10 with no replacement at all; UX_SPEC §2 mandates a 2px accent ring that no P1 step implements; and axe-core 4.14 (the T-109 gate) has **no** focus-appearance rule, so the automated gate cannot detect it. The token for the correct ring already exists and measures 5.22–6.44:1 against every surface.
3. **`fontSize: "13.5px"` remains in `cmTheme.ts`.** UX_SPEC §2 says code text is 13/20. T-102's spec did not list changing it, so it is untouched; it is the only off-scale type value in the app.
4. **Off-scale density.** `text-xs` (12px) appears 142 times in source against a spec whose body default is 14/22. Not a T-102 concern, but it will affect how the redesign reads at CP1.
5. **`copyText()` discards its boolean result** in `DebugReportApp.copySanitized`, so a failed copy still toasts "Copied". Logged for T-108's shared `CopyButton`; see the same finding file.
