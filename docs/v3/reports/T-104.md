## Deviations from the spec
1. **The two `theme-color` metas were moved outside the SEO markers.** `renderHead()` emits title, description, canonical, og:* and twitter:card — but not theme-color. Left inside, the markers would have deleted them on every generated page. The spec's list of tags to wrap did not include theme-color, so this follows the spec's intent.
2. **My first `headers_csp_per_page` implementation was wrong and the suite caught it.** I wrote the "no CSP on the wildcard block" assertion as a regex with `(\s+[^\n]*\r?\n)*`, but `\s` matches newlines, so the pattern spanned into later blocks and reported a CSP on `/*` that was not there. It failed for the right reason (a false positive in the test, not in the output). Rewritten to split `_headers` into blocks on blank lines and assert against the `/*` block and the `/jwt-decoder/` block separately; verified standalone before re-running (21 blocks, wildcard has no CSP, jwt block does).
3. `manualChunks` was added to `vite.config.ts` as step 5 of the spec requires; without it Rollup would have duplicated CodeMirror into each tool chunk.

## Questions / risks for the reviewer
1. **The codemirror shared chunk is 173 kB gzip and is the largest single asset.** It is inside the rule's allowance, but it is also preloaded on the home page (`<link rel="modulepreload" href="/assets/codemirror-…">`), which costs a first-load download for someone who only wants, say, the JWT decoder. Moving editors to a per-tool dynamic import, or dropping the preload for tools that do not need it, would improve the home-page first paint. Not in this task's scope.
2. `vite preview` answers unknown paths with `200` + the app shell. On Netlify `404.html` is served instead. The in-app notfound route is T-106's job; nothing here asserts the status code.
3. `document.title` is set on the client from `route`, and the prerendered pages carry their own `<title>`. They agree because both use `tool.title`, but a future rename must change both paths (meta and router) — worth a comment at CP1.
4. `README` still says "Counters are off unless a build sets `VITE_GC_CODE`", which stays true; the counters paragraph was kept per the spec.
