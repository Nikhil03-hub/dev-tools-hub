## Deviations from the spec

Four deliberate ones, each with the evidence that forced it. The other spec text is followed literally.

**D1 — detector regex widened.** The spec's `^\s*(- |[\w"'.-]+:\s)` requires whitespace *after* the colon, so a block-mapping parent (`metadata:`, `spec:`, `labels:`) never matches. Measured on the spec's own Kubernetes example: **7 of 12 lines matched = 0.583**, under the 0.6 threshold — the rule as written could not detect the file type named in the tool's own keywords. `test/e2e.cjs` would then have had no YAML to detect.
Fix: `^\s*(- |[\w"'.-]+:(\s|$))`, and comment lines are kept out of the denominator because they carry no structure. A first-line guard (`YAML_FIRST`) is retained so an HTTP message — whose `Host:` / `Accept:` lines are 2 of 3 = 0.67 — still does not present as YAML. Now 11/11 on the manifest. Both negatives are unit-tested.

**D2 — bulleted lists are detected, and that is correct.** `"‑ buy milk\n- call the dentist"` scores as YAML. It is not a false positive: `- x` *is* a YAML sequence, and `yamlToJson` genuinely converts it to `["buy milk", …]` (verified: `[\n  "buy milk",\n  "call the dentist",\n  "ship the release"\n]`). The chip says "Looks like YAML" at 0.65, which is true. Recorded as `does fire on a bare bulleted list` rather than suppressed.

**D3 — `language="yaml"` renders as plain text.** The spec says "the output is a read-only CodeArea"; the repo's shared read-only surface is `JsonEditor`, whose grammars are JSON and TS. Feeding YAML through the JSON grammar would mis-colour it and mark it invalid, and a YAML grammar is a new dependency. So `yaml` selects no grammar — correct text, no colour. Documented in the file.

**D4 — error messages state their coordinates once.** `prettyErrors` puts `"… at line 2, column 1:"` inside the message, and the spec also returns line/column separately, so the literal reading renders *"…at line 2, column 1: (line 2, column 1)"*. The trailing duplicate is stripped only when coordinates are present. Still "the first line of `e.message`" in substance; `yaml_json_error_coordinates_once` guards it.

Also: `related` uses `["json-workbench", "debug-report"]` exactly as the spec directs until `csv-json` and `toml-json` exist.
