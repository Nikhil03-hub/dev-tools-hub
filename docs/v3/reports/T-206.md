papaparse is used as the spec directs (`Papa.parse` with `header`, `skipEmptyLines: true`, `dynamicTyping`) and for RFC 4180 emitting (`Papa.unparse`). Two library behaviours were measured rather than assumed, and both changed the design:

- **papaparse renames duplicate headers to `a_1` and calls `console.warn`.** That is silent data renaming plus console noise in a product whose e2e gate reports warnings. So ambiguous header rows are refused *before* the library sees them.
- **`Papa.unparse` writes a nested object as `[object Object]` and a nested array as `1,2`** — data destroyed behind a plausible-looking cell. Nested values are therefore converted to JSON text here, before the emitter runs, exactly as the spec requires.
- The library's own `escapeFormulae: true` was **not** used: it force-quotes the escaped cell, and the spec fixes the exact output `f\r\n'=SUM(A1)` unquoted. The rule (`/^[=+\-@\t\r]/`, strings only) is implemented here instead, matching the library's set.

## The data contract

CSV and JSON do not hold the same information, so the contract is stated in the module header and each lossy or ambiguous case is either refused or announced. Where the spec is silent, the choice below is the narrowest defensible one.

**CSV → JSON**

| Input | Behaviour |
|---|---|
| `a,a` duplicate headers, or two blank headers | **refused**, naming the columns and pointing at "Header row off". Nothing half-converted. |
| `__proto__` header | **refused** — measured: papaparse drops that column's data entirely. |
| `constructor`, `prototype`, `A`/`a`, `" a "` | accepted as written; no trimming, no case-folding, no renaming (measured: papaparse keeps them as own keys). |
| one blank header | accepted, warned: *its JSON key is an empty string*. |
| row with extra cells | kept under `__parsed_extra` + the spec's `Row 1: Too many fields…` warning. |
| row with missing cells | key omitted + `Row 1: Too few fields…` warning. |
| unterminated / malformed quotes | kept as a row, reported as warnings (`Row 2: Quoted field unterminated`), first 20 only. |
| `00123`, `true`, empty cell | **text** by default. `Detect numbers` is opt-in; when on, every column it rewrote is named in a warning (leading zeroes lost, empty→`null`, `1e3`→`1000`, `" 1 "`→`1`), from a bounded second read of the first 200 rows. |
| dates | never inferred — `2026-10-25` stays a string (papaparse has no date coercion; asserted). |
| UTF-8 BOM | stripped from the first header name (measured, then asserted). |
| CRLF, LF, no final newline, blank lines | all handled; a line of only delimiters is data, not a blank line. |
| header row only | `[]`, 0 rows, warned rather than presented as an empty success. |
| `header: false` | array of arrays, `columns: []`, and duplicate names are no longer a collision. |
| empty / whitespace / BOM-only input | error. Over 2,000,000 characters | error, with the limit in the message. |

**JSON → CSV**

| Input | Behaviour |
|---|---|
| array of objects | columns = union of keys in first-seen order, so a key appearing only in row 9 still gets a column. |
| array of arrays | one row each, no header invented; differing lengths warned. |
| mixed objects and arrays, primitive or `null` items | **refused**, naming the item position and its type. (Needed: `Papa.unparse` throws `Unable to serialize unrecognized input` on `[1,2,3]`.) |
| root object / string / number / `null` | refused, with the `[{…}]` fix spelled out for an object. |
| nested object or array | JSON text inside the cell + the spec's sentence *Nested values in columns a, b were written as JSON text.* |
| `null` value or absent key | empty cell, warned once, in file column order, because CSV cannot tell them apart. |
| `=SUM(A1)`, `+1`, `-1`, `@1`, tab- or CR-led **strings** | `'` prefix when Formula protection is on; numbers are never touched (`-5` stays `-5`). |
| same, protection off | written as-is **plus** a warning that N cells can run as a formula and how to turn it on. |
| `[]`, `[{}]`, `[[]]` | empty CSV, each with its own explanation — never a silent blank result. |
| `__proto__` key | preserved as a column (rows are built with `Object.create(null)`, so the assignment cannot redefine a prototype), and warned that the reverse direction refuses that name. |

Formula protection is **off by default**, because it edits exported text and the product rule is fidelity first; it is announced in both directions. The warning states plainly that the apostrophe makes a spreadsheet treat the cell as text and is *not* a guarantee against formula-injection tricks — standard CSV quoting is not mentioned as protection anywhere.

## Deviations from the spec

**D1 — ambiguous header rows are refused, not renamed.** The spec does not say what `a,a` should do. papaparse renames the second to `a_1` and `console.warn`s; that is a silent rename of a key the user will code against. The refusal keeps every cell recoverable ("turn Header row off to keep every column by position"). *Question for the reviewer:* if a collision-tolerant mode is wanted, `__parsed_extra`-style suffixing preserves data too — but it changes names, so it is not the default here.

**D2 — formula protection defaults to off.** The spec lists it as an option; it does not set a default. Off keeps exported text identical to source text, and the risk is then stated as a warning with the remedy named in the same sentence. Flipping the default is a one-line change if the reviewer prefers safety-over-fidelity.

**D3 — header cells are not formula-protected.** `Papa.unparse` looks each cell up by its column name, so protecting a header means renaming it, and two different headers can collide after the prefix (`'=A` and `=A`). Data cells follow the spec exactly; a formula-looking *column name* is exported as written and warned about explicitly. The FAQ's claim is about cells, and the report does not claim more than the code does.

**D4 — the detector requires a "tight" delimiter.** The spec's rule, measured against real text, fires on prose: *"Hello, world / Goodbye, friend / See you, later"* is three lines with the same single comma. In English a comma is followed by a space; in a CSV export the next field follows immediately. Requiring at least one delimiter not followed by a space keeps every export shape tested (comma, semicolon, tab, pipe, quoted commas, embedded newlines, CRLF, blank lines) and drops the prose case. **Known cost:** a hand-typed file spaced like sentences (`name, age` / `Ana, 30`) is not detected — it still converts perfectly once opened.

**D5 — the detector also requires all inspected records to agree,** not merely two of five, and refuses anything that parses as JSON or starts with `{`/`[`. Measured afterwards against a 21-sample corpus (in [CP2-EVIDENCE-PACKET.md](CP2-EVIDENCE-PACKET.md) §3): the JSON exclusion and the tight-delimiter rule do the precision work, and **the all-agree clause buys no additional precision at all** while costing two real CSV forms (a trailing footer line, one unquoted stray comma). The honest reading is that D5's first half was over-restriction; dropping it leaves the rule equal to the spec plus the two guards that are justified. Recorded, not changed — Batch A is frozen for CP2.

**D6 — the Table tab re-reads the produced JSON** rather than keeping a second internal copy. The spec's `csvToJson` returns `json` and a row count, not rows, and the parse only runs while the Table tab is open (memoised on the output string), so the common path pays nothing. A `rows: unknown[]` field on the result would be a cleaner shape; it is not what the spec's signature says.

## Findings for the reviewer

- **Two of my own assertions were vacuous, and only running the suite told me.** `download.path()` returns a promise, so `readFileSync(dl.path())` threw inside a `try` that swallowed it — a real `.csv` file read as `null`. The populated-theme check read the editor container, whose text begins with CodeMirror's line-number gutter (`1\n2\n3…`), so it would have passed for any populated page. A **third** gap was caught by reasoning before it could mislead: the duplicate-header test matched a phrase its own fallback path also emits, so it was tightened first (M1 above) and the mutation then failed one test instead of surviving silently. All three are in `c01ffac`, with the reasons in the commit message.
- **papaparse's console noise is a correctness signal.** Finding the `console.warn` in the duplicate-header path explained why the library's rename behaviour must not be reachable from a tool whose gate asserts a clean console. The pre-check runs `Papa.parse` with `header: false, preview: 1`, which was measured to detect the same delimiter as the full parse on six samples (including a quoted-comma file) — so the header is validated against the delimiter the data will use, and that value is then passed to the real parse rather than re-detected.
- **Two defects the unit tests missed and the built page showed** were in warning copy, not conversion: `1 cell start with…` and an empty-cell list ordered by discovery (`f, a, b`) instead of file order. Both are now regression tests.
- **`Papa.unparse` throws** `Unable to serialize unrecognized input` for `[1,2,3]`, which is why the row-shape validator exists rather than a try/catch around the emitter — and why M6 is a meaningful mutation.
- One `Math.max(...widths)` was replaced with a single pass: spreading a 1 M-row array would have thrown `RangeError` on exactly the inputs the tool is meant to handle.

## Limitations and what remains unverified

- `Detect numbers` names affected columns from the **first 200 rows** only; the rewrite itself is not bounded, so a leading zero past row 200 is converted without a warning sentence naming it. The general warning about the option is not shown in that case either — this is a deliberate cost bound, not an oversight. **Measured after the review questions came in:** the boundary is exactly row 200 warned / row 201 silent, and it is now recorded with reproduction steps and a bounded repair proposal in [CP2-EVIDENCE-PACKET.md](CP2-EVIDENCE-PACKET.md) §4. Not changed here: Batch A is frozen for review.
- Duplicate headers are refused rather than renamed; a real-world export with two `Total` columns therefore needs "Header row off" to convert at all.
- Chromium only: Firefox, Safari, iOS and a real screen reader remain unverified, as at CP1.axe measures the DOM, not a reader's announcement.
- The 1.2 M-character e2e case proves the manual gate on a comment-free file; a genuinely wide file (10,000 columns) has not been measured in the browser.
- Formula protection follows the spec's character set. It is not a sandbox: a spreadsheet's behaviour on `'` is version-dependent, and nothing here claims otherwise.
- `papaparse` remote/worker modes are untouched and unreachable from this module (`download` and `worker` are never passed); the boundary gate still proves no network API appears in pure code.
